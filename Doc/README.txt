工业现场数据采集与控制终端
============================

1. CAN 基础参数
---------------

- 类型：经典 CAN 2.0
- 波特率：1 Mbit/s
- 心跳帧：标准 ID 0x123，每秒发送一次
- 命令帧：标准 ID 0x321
- 响应帧：标准 ID 0x322

2. 命令帧格式
-------------

Byte0：命令码
Byte1：请求序号，响应会原样返回
Byte2~Byte7：命令参数

3. 响应帧格式
-------------

Byte0：命令码 | 0x80
Byte1：请求序号
Byte2：执行结果
Byte3~Byte7：返回数据

执行结果：

- 0x00：执行成功
- 0x01：不支持的命令
- 0x02：请求长度不足
- 0x03：数据尚未准备好
- 0x04：参数非法

4. 支持的命令
-------------

0x01 PING

请求示例：01 5A 00 00 00 00 00 00
响应示例：81 5A 00 50 4F 4E 47 01

其中 50 4F 4E 47 是 ASCII 字符 PONG，最后的 01 是协议版本。

0x02 GET_STATUS

请求示例：02 5B 00 00 00 00 00 00

响应数据：

- Byte3：HAL CAN 状态
- Byte4：HAL CAN 错误码低 8 位
- Byte5：接收帧计数低 8 位
- Byte6：接收帧计数高 8 位
- Byte7：FreeRTOS 接收队列溢出计数低 8 位

0x03 CLEAR_COUNTERS

请求示例：03 5C 00 00 00 00 00 00
响应示例：83 5C 00 00 00 00 00 00

该命令清零 CAN 接收、接收错误、队列溢出和应用层命令/响应统计。

0x04 GET_CAN_DIAGNOSTICS

请求示例：04 5D 00 00 00 00 00 00

响应数据：

- Byte3：Bus-Off 累计次数低 8 位
- Byte4：Bus-Off 成功恢复次数低 8 位
- Byte5：Bus-Off 软件恢复失败次数低 8 位
- Byte6：CAN 错误中断次数低 8 位
- Byte7：最近一次 HAL CAN 错误码低 8 位

0x05 GET_ANALOG

请求示例：05 5E 00 00 00 00 00 00

响应数据：

- Byte0：0x85
- Byte1：请求序号
- Byte2：执行结果
- Byte3：ADC 原始值低 8 位
- Byte4：ADC 原始值高 8 位
- Byte5：估算电压 mV 低 8 位
- Byte6：估算电压 mV 高 8 位
- Byte7：采集有效标志，1 表示有效

0x06 SET_OUTPUT

请求格式：

- Byte0：0x06
- Byte1：请求序号
- Byte2：通道号，0 或 1
- Byte3：目标状态，0 断开、1 闭合

请求示例（闭合通道 0）：06 61 00 01 00 00 00 00

响应数据：

- Byte0：0x86
- Byte1：请求序号
- Byte2：执行结果
- Byte3：通道号
- Byte4：该通道执行后的实际状态
- Byte5：全部通道状态位图
- Byte6：支持的通道总数

0x07 GET_OUTPUT

请求示例：07 62 00 00 00 00 00 00

响应数据：

- Byte0：0x87
- Byte1：请求序号
- Byte2：执行结果
- Byte3：全部通道状态位图，bit0 是通道 0
- Byte4：通道 0 状态
- Byte5：通道 1 状态
- Byte6：支持的通道总数
- Byte7：成功执行的输出命令次数低 8 位

5. CAN 接收队列
---------------

- 队列容量：16 帧
- CAN 中断使用 xQueueSendFromISR() 投递完整报文
- CAN_Service 任务使用 xQueueReceive() 阻塞等待报文
- 收到报文后，中断会立即唤醒 CAN_Service 任务
- 队列为空时任务不占用 CPU，每 10 ms 超时一次以检查心跳和 Bus-Off
- 队列满时保留已经排队的旧报文，丢弃新报文
- 每次丢弃都会增加队列溢出计数，可通过 GET_STATUS 的 Byte7 查询

6. Bus-Off 检测和恢复
--------------------

- 开启 Error Warning、Error Passive、Bus-Off 和 CAN Error 中断
- Bus-Off 中断只记录状态，不在中断中停止或重启 CAN
- 优先使用 bxCAN 的 ABOM 功能按 CAN 规范自动恢复
- Bus-Off 持续 1000 ms 时，CAN 服务任务停止并重启 CAN 作为软件兜底
- 可通过 GET_CAN_DIAGNOSTICS 查询 Bus-Off 和恢复统计

7. FreeRTOS 任务结构
-------------------

- 内核版本：FreeRTOS Kernel V10.3.1
- 系统节拍：1000 Hz，即每个 tick 为 1 ms
- CAN_Service 任务：优先级 2，处理命令、Bus-Off 恢复和实际心跳发送
- Heartbeat 任务：优先级 1，每 1000 ms 向 CAN_Service 任务发送一次通知
- Acquisition 任务：优先级 1，每 100 ms 采集一次 PA0 电位器电压
- Modbus 任务：优先级 1，阻塞等待 RS485 帧队列，完成协议解析和响应
- Watchdog 任务：优先级 2，每 100 ms 检查一次任务健康，全员健康才喂狗
- Heartbeat 任务不直接操作 CAN，避免两个任务同时访问 HAL CAN
- CAN 接收使用 16 帧 FreeRTOS Queue，在中断与 CAN_Service 任务间传递报文
- RS485 接收使用 2 帧 FreeRTOS Queue，在中断与 Modbus 任务间传递完整帧

看门狗与任务健康监测：

- IWDG 独立看门狗：LSI 40 kHz 32 分频，超时约 1 秒，启动后无法软件停止
- 主时钟崩溃时 LSI 照常运行，是真正能兜底的复位源
- 每个任务每轮主循环向 watchdog.c 报到一次，记录最近报到时间
- 任务最迟报到期限：CAN_Service 200 ms、Heartbeat 2500 ms、
  Acquisition 500 ms、Modbus 1500 ms（按各自正常周期的 2~3 倍设定）
- Watchdog 任务每 100 ms 检查一次：有任何任务超期未报到就停止喂狗，
  约 1 秒内 IWDG 复位整块板子；卡死任务名会先通过调试串口打印
- 调试器暂停内核时 IWDG 同步暂停（DBGMCU 冻结位），单步调试不会误复位
- 看门狗复位次数记录在备份寄存器 BKP->DR1，复位不丢失，
  可通过 Modbus 保持寄存器 7 读取；健康位图见保持寄存器 6
- 复位后输出回到全部断开状态，与上电默认安全策略一致
- 产线测试：Modbus 0x06 向命令寄存器 0 写入 0xDEAD，先回显响应，
  随后 Modbus 任务原地空转模拟卡死，可实测整条复位链路

8. PA0 模拟量采集
-----------------

- ADC 外设：ADC1 通道 0
- 输入引脚：PA0
- ADC 分辨率：12 位，原始值范围 0~4095
- ADC 时钟：12 MHz
- 采样周期：100 ms
- 参考电压：按 3300 mV 估算
- 电压换算：raw * 3300 / 4095
- 电位器两端必须接 3.3V 和 GND，PA0 不允许输入 5V

9. 数字输出控制
---------------

- 输出通道数：2
- 通道 0：PB0
- 通道 1：PB1
- 输出模式：推挽输出，低速档
- 有效电平：高电平表示闭合，低电平表示断开
- 上电默认：全部断开，避免继电器误动作
- 控制命令：0x06 SET_OUTPUT
- 查询命令：0x07 GET_OUTPUT
- 提供 GPIO_Output_All_Off() 用于故障时紧急断开

10. RS485 与 Modbus RTU 从站
----------------------------

硬件连接：

- 模块：野火 RS485 通信模块，3.3V 供电
- 外设：USART2，默认 115200 8N1
- PA2：USART2_TX，连接野火模块 TXD（已实测确认）
- PA3：USART2_RX，连接野火模块 RXD（已实测确认）
- PB10：连接模块 DIR，低电平接收，高电平发送
- 模块 3.3V：连接核心板 3.3V
- 模块 GND：连接核心板 GND
- 模块 A/B：连接 USB-RS485 适配器的 A/B，A 对 A、B 对 B

Modbus RTU 从站：

- 从站地址：1（编译期常量，见 app_modbus.h）
- 帧边界：USART2 空闲线（IDLE）中断检测帧结束；中断把整帧放入
  2 帧深度的 FreeRTOS 队列，Modbus 任务阻塞取帧并完成解析
- CRC16：多项式 0xA001、初值 0xFFFF，按位计算（比查表省 512 字节 Flash）
- CRC 错误、地址不符、帧太短的帧一律静默丢弃，符合 Modbus 规范
- 广播（地址 0）只执行写线圈，任何情况下都不回复

支持的功能码：

| 功能码 | 作用 | 地址范围 | 说明 |
|--------|------|----------|------|
| 0x01 | 读线圈 | 0~1 | 返回 PB0/PB1 输出状态位图 |
| 0x03 | 读保持寄存器 | 0~7 | 从站信息/通信统计/看门狗状态 |
| 0x04 | 读输入寄存器 | 0~2 | ADC 原始值/毫伏值/采集有效标志 |
| 0x05 | 写单线圈 | 0~1 | 0xFF00 闭合、0x0000 断开，支持广播 |
| 0x06 | 写命令寄存器 | 仅 0 | 写 0xDEAD 触发看门狗卡死测试，支持广播 |

命令寄存器（0x06 写入，地址 0）：

- 0xDEAD：看门狗卡死测试，先回显响应，再让 Modbus 任务原地空转，
  用于实测“任务卡死 -> 停止喂狗 -> IWDG 复位”的完整链路

输入寄存器映射（0x04）：

- 寄存器 0：ADC 原始值，范围 0~4095
- 寄存器 1：估算电压，单位 mV
- 寄存器 2：采集有效标志，1 表示有效

保持寄存器映射（0x03）：

- 寄存器 0：从站地址（当前为 1）
- 寄存器 1：寄存器映射版本（当前为 1）
- 寄存器 2：有效请求帧计数低 16 位
- 寄存器 3：CRC 错误帧计数低 16 位
- 寄存器 4：异常响应计数低 16 位
- 寄存器 5：正常响应计数低 16 位
- 寄存器 6：任务健康位图，bit0~bit3 对应 4 个任务，0x0F 表示全部健康
- 寄存器 7：看门狗复位累计次数（存于备份寄存器，复位不丢失）

异常响应：0x01 非法功能码、0x02 非法地址、0x03 非法数据。

Modbus 通信示例（从站地址 01）：

- 读 ADC 原始值：`01 04 00 00 00 01 31 CA`，
  响应 `01 04 02 07 08 xx xx`，数据区 07 08 即原始值 0x0708 = 1800
- 闭合 PB0：`01 05 00 00 FF 00 8C 3A`，响应原样回显前 6 字节加 CRC
- 断开 PB0：`01 05 00 00 00 00 CD CA`
- 读 2 路线圈：`01 01 00 00 00 02 BD CB`，响应 `01 01 01 01 xx xx` 表示 PB0 闭合

CAN 测试命令（保留，仅在没有 Modbus 主机轮询时使用）：

- `0x08 RS485_SEND`：Byte2 为长度，Byte3~Byte7 为最多 5 个待发送字节。
  注意：该命令发送的原始字节会破坏 Modbus 帧边界，仅限离线调测
- `0x09 RS485_STATUS`：返回接收字节数、发送次数、错误次数、最近字节和错误码
- 发送示例：`08 81 03 11 22 33 00`，STM32 会通过 RS485 发送 `11 22 33`

11. 系统数据流
---------------

```text
电位器/模拟传感器
        |
        v
PA0 -> ADC1 -> Acquisition_Task -> 最新采样快照
                                      |
                                      v
                              CAN 命令 0x05 查询

PCAN/现场 CAN 设备 -> CAN 收发器 -> CAN1
                                      |
                                      v
                          CAN 中断 -> FreeRTOS Queue
                                      |
                                      v
                              CAN_Service_Task
                                      |
                          +------------+------------+
                          |                         |
                          v                         v
                     协议响应                 PB0/PB1 输出
                                                    |
                                                    v
                                           继电器/LED/执行器

Modbus 主机/PLC -> RS485 模块 -> USART2
                                      |
                                      v
                     字节中断填帧缓冲 -> IDLE 中断判帧结束
                                      |
                                      v
                          2 帧 FreeRTOS Queue
                                      |
                                      v
                                 Modbus_Task
                          （CRC16 + 功能码分发 + 响应）
```

12. 硬件引脚分配
----------------

| 引脚 | 功能 | 当前用途 |
|------|------|----------|
| PA0 | ADC1 通道 0 | 电位器或 0~3.3V 模拟传感器输入 |
| PA9 | USART1_TX | 调试日志发送到 CH340 |
| PA10 | USART1_RX | 调试串口接收预留 |
| PA11 | CAN1_RX | 连接 CAN 收发器 RX |
| PA12 | CAN1_TX | 连接 CAN 收发器 TX |
| PB0 | 数字输出通道 0 | 继电器/LED 控制信号 |
| PB1 | 数字输出通道 1 | 继电器/LED 控制信号 |
| PA2 | USART2_TX | 野火 RS485 模块 TXD |
| PA3 | USART2_RX | 野火 RS485 模块 RXD |
| PB10 | GPIO 输出 | RS485 模块 DIR |

注意：PB0/PB1 是输出，不是设备数据输入。要读取设备实际运行反馈，需要另设数字输入引脚，并根据设备电压增加分压、光耦或输入保护电路。

14. 当前版本定位
-----------------

当前版本是一个已经完成主要功能并通过实机验证的 STM32 工业现场采集与控制终端原型，适合用于实习项目展示和技术面试。它已经具备从模拟量采集、CAN 通信到数字输出控制的完整闭环，但仍应在正式工业部署前完成可靠性增强和硬件安全验证。

15. 面试讲解要点
-----------------

- 为什么逐步从裸机迁移到 FreeRTOS：先保留已验证驱动，再降低迁移风险。
- 为什么使用 FreeRTOS Queue：中断只搬运报文，任务阻塞等待，避免主循环轮询和复杂中断处理。
- 为什么由 CAN_Service_Task 独占 HAL CAN：避免多个任务并发访问 CAN 句柄和发送邮箱。
- 如何处理 CAN 错误：中断记录 Error Warning、Error Passive 和 Bus-Off，任务完成恢复操作。
- ADC 如何工作：ADC1 通道 0 采集 PA0，12 位原始值按 `raw * 3300 / 4095` 换算毫伏。
- GPIO 如何工作：CAN 命令经过队列和协议解析后控制 PB0/PB1，并返回实际软件状态。
- 如何验证：使用 PCAN-USB 发送协议帧，使用串口查看日志，使用万用表验证 GPIO 电平。
- Modbus 如何划分一帧：RTU 模式靠总线静默间隔分帧，用 USART 空闲线（IDLE）中断检测帧尾，比软件定时器简单且实时性好。
- 为什么 CRC 错误的帧静默丢弃：Modbus 规范明确要求，避免对损坏帧作答而加剧总线混乱，同时计数供诊断。
- RS485 方向切换的时机：阻塞发送等最后一个停止位离总线后才把 DIR 切回接收，防止截断自己发出的最后一个字节。
- 为什么看门狗不直接在所有任务里喂：某个任务卡死时狗照样被喂等于白养；改成每个任务只报到、由喂狗任务做“全员健康才喂”的闸门，单个任务假死也能触发复位。
- 为什么用 IWDG 而不是 WWDG：IWDG 用独立 LSI 时钟，主时钟崩溃也能复位，是工业现场真正的兜底手段。

16. 后续增强计划
-----------------

以下内容不是当前版本的已完成能力，后续可按需要逐步增加：

- ADC 多次采样平均、中值滤波和上下限报警
- 收窄 CAN 接收过滤器，减少无关报文中断

- 扩展 Modbus 功能码（0x06/0x10 写保持寄存器、0x0F 写多线圈）
- 增加更多现场传感器接口
- 进行长时间运行、满载 CAN、掉电和异常复位测试
