# STM32F103 工业现场数据采集与控制终端

一个跑在 STM32F103C8 上的小型工业终端：采集一路模拟量，控制两路开关量输出，同时挂了两条总线——CAN 走自定义协议，RS485 走标准 Modbus RTU 从站。两条总线读的是同一份数据，上位机想走哪条都行。

这个项目一开始是裸机 + CAN 收发的练手，后来一步步加上了 FreeRTOS、Modbus、看门狗，每一步都在实物上验证过。代码里中文注释比较多，都是自己当时踩坑记下来的，比较口语化，凑合看。

## 硬件

全部是很便宜的东西，淘宝加起来一百多块：

- 野火小智 STM32F103C8 核心板
- CAN 收发器模块（接 PA11/PA12）
- USB-CAN 分析仪（PCAN 兼容的那类，当 CAN 上位机）
- 野火 TTL 转 RS485 模块（USART2，PB10 控方向）
- USB 转 RS485（CH340，电脑上当 Modbus 主站）
- 一个电位器接 PA0，PB0/PB1 接万用表（或者继电器模块）

## 软件结构

Keil MDK 工程，FreeRTOS V10.3.1，一共 5 个任务：

| 任务 | 干什么 |
|---|---|
| CAN_Service | 只有它碰 CAN 外设。等队列收命令帧，解析，回响应帧，顺便处理 Bus-Off 恢复 |
| Heartbeat | 每秒发一帧 0x123 心跳 |
| Acquisition | 100ms 采一次 PA0，临界区保护写快照 |
| Modbus | 等 RS485 帧队列，做 CRC 校验和功能码分发 |
| Watchdog | 健康闸门，见下面 |

整体思路是"中断只搬运，任务做协议"：CAN 中断把整帧报文丢进 FreeRTOS 队列，RS485 的字节中断往帧缓冲里攒，IDLE 中断发现总线空闲就把整帧入队。中断里不做任何协议解析，队列满了丢新帧保旧帧并计数。

分层大概是：

```
APP/     应用层，CAN协议解析、Modbus功能码、采集逻辑、任务创建
User/    驱动层，can/rs485/adc/gpio_output/usart/watchdog
Middlewares/  FreeRTOS
Libraries/    STM32 HAL
```

## CAN 协议

1 Mbps，心跳帧 0x123，命令帧 0x321，响应帧 0x322。响应格式固定 8 字节：命令码|0x80、原样返回的序号、结果码、数据。

支持 9 条命令：PING、GET_STATUS、CLEAR_COUNTERS、GET_DIAGNOSTICS、GET_ANALOG、SET_OUTPUT、GET_OUTPUT、RS485_SEND、RS485_STATUS。具体帧格式在 Doc/README.txt 里有带 CRC 的实例帧，拿来就能发。

## Modbus RTU 从站

115200 8N1，从站地址 1。帧定界用的是 IDLE 中断——115200 下大约 87us 就能发现总线空闲，比规范要求的 t3.5 还早，对遵守规范的主机是安全的。

寄存器映射：

- 0x04 读输入寄存器：0=ADC 原始值，1=毫伏值，2=有效标志
- 0x01 读线圈：PB0/PB1 输出状态
- 0x05 写单线圈：0xFF00 闭合 / 0x0000 断开，支持广播
- 0x03 读保持寄存器：0~7，从站地址、版本号、请求/响应/CRC错/异常计数、任务健康位图、看门狗复位次数
- 0x06 写单寄存器：地址 0 写 0xDEAD 触发看门狗卡死测试

CRC 错误、地址不符、帧太短都按规范静默丢弃。异常码 0x01/0x02/0x03。

几个可以直接抄去测的帧（COM 口 115200 8N1）：

```
01 04 00 00 00 01 31 CA    读 ADC 原始值
01 05 00 00 FF 00 8C 3A    闭合 PB0
01 01 00 00 00 02 BD CB    读两路线圈
01 03 00 00 00 08 44 0C    读全部 8 个保持寄存器
01 06 00 00 DE AD 11 D7    看门狗卡死测试（慎用，板子会复位）
```

## 看门狗

这块花的时间最多，也是我觉得最值得讲的部分。

最简单的喂狗是在某个循环里刷 IWDG，但这样有漏洞：只要喂狗的那个任务活着，别的任务死光了狗也不会叫。所以这里做的是每个任务跑一轮就给自己"报到"，喂狗任务每 100ms 检查一遍，全员都在期限内报到过才喂。任何一个任务卡死，喂狗就停，IWDG 大约 1 秒后复位整块板子。

几个细节：

- 复位原因在启动时判断，狗复位次数存 BKP 备份寄存器（断电才丢），通过 Modbus 保持寄存器 7 能在线读——设备能自己报告被狗救过几次
- LSI 有误差（30~60kHz），真实超时在 0.67~1.33 秒之间，喂狗周期 100ms 留了足够余量
- 置了 DBGMCU 冻结位，单步调试时狗会暂停，不然调几秒就被复位

卡死测试是真的测过的：写 0xDEAD 后 Modbus 任务先回显响应然后原地空转，大约 2 秒内板子被复位，复位计数从 0 变 1。

## 测试记录

都在实物上跑过的，详细数据在 Doc/README.txt 第 13 节：

- Keil 全量构建 0 Error 0 Warning，Flash 22.9KB / 64KB，RAM 8.5KB / 20KB
- CAN 12 帧 PING 突发，12/12 响应，队列溢出 0
- Modbus 20 帧连续轮询全部应答，CRC 全对，队列溢出 0
- 异常路径：非法地址回 0x85+0x02，未支持功能码回 0x86+0x01，CRC 错和别的站地址静默
- 广播写线圈静默执行，读线圈能确认生效
- 看门狗：健康位图 0x0F，0xDEAD 假死后约 2 秒复位恢复，复位计数 0→1
- ADC 电位器实测 183~1784，PB0/PB1 万用表实测 3.3V/0V
